## 决策与阻塞
- **状态机加 peek/eat 而不是用 idle 顶替**：状态机是后续行为决策的单一来源（pet_window / behavior / feeding 都查它），如果用 idle 顶替吸边状态，behavior 自主行为可能误判桌宠在巡游、走起来从屏幕外溢出。加专门状态做"逻辑闸门"更稳。
- **Phase A/B 拆分**：CLAUDE.md 硬约束 #6 明文"美术资源缺失时用占位图，禁止因为没有真实美术而停下开发"。代码 + 占位先落地能跑，prompts 写齐让用户随时出图直接接入。
- **dizzy 把手画进 sprite 而不是独立 overlay**：用户决策——独立层要做坐标跟随 + z-order + 镜像三件事，画进同一张图所有问题消失，只要美术保证手位一致。
- **peek 单方向出图**：和 walk 一致，用户出朝左缘扒边 + 朝右看，代码用 set_direction 自动镜像出右缘版本。出图量减半。
- **咀嚼时长 3s + happy 0.8s**：用户决策——eat 是主体（看小喜咬东西），happy 是收尾（"吃完一阵高兴"），所以 eat 长 happy 短。
- **狗粮走 _DOGFOOD_PATTERN 占位**：和 bone 一致的兜底策略，render_pattern 输出像素卡通风。用户出 dogfood.png 后自动绕开占位。
- **focus_lock 提示文案对应食物 emoji**：骨头用 🦴 / 狗粮用 🥣，给用户即时反馈"我点的是哪个"。

- 其他状态保持原路径（`KeepAspectRatio` 缩到 size×size）不变

#### Bug 2：狗粮 eat → idle → happy 闪烁的真根因（二轮修不彻底）
- 二轮我加了 `_begin_eat` 头部 `behavior.pause()`，骨头路径有效但狗粮路径仍闪
- 真根因：[src/pet/pet_window.py:contextMenuEvent] 的 `menu.aboutToHide.connect(lambda: QTimer.singleShot(0, self._resume_behavior_if_not_focused))` 把 resume 排到了下一个事件循环
  - 骨头路径：`_start_bone` 是异步动画（500ms 飞落 + walk_to）→ 排队的 resume 在 _begin_eat 之前就触发，那时 pause behavior 还没开始，无影响
  - 狗粮路径：`_start_dogfood` → `_begin_eat`（同步）→ `behavior.pause()` 当场生效；之后下一个事件循环排队 resume 触发 → 把刚 pause 的 behavior 又唤醒 → behavior 在 eat 3s 期间偷偷切一次 idle → 看到 eat → idle → happy 闪烁
- [src/pet/pet_window.py] `_resume_behavior_if_not_focused` 加状态守卫：`if self._state_machine.state() in ("eat", "hold_bone", "happy"): return`
- 三个状态都加是因为：eat / hold_bone 是吃食主体不能被 behavior 切走；happy 是吃完后的庆祝阶段，behavior 切走会破坏 0.8s 弹跳

## 决策与阻塞（M4.9 四轮）
- **dizzy 走窗口 dynamic resize 而不是改 PET_SIZE 全局变大**：1.4× 后 179 是 dizzy 一个状态的特殊需求；其他 9 个状态都按 128 处理。改 PET_SIZE 等于全状态都要按 179 重排（碰撞 / 走路 / 拖动），代价远大于一个 resize handler
- **drag_offset 用 delta 修正而不是重算**：mouseMoveEvent 里 `new_pos = cur - drag_offset`，如果 resize 后不修正，下一帧鼠标移动会把窗口拽回原位（drag_offset 还记着旧 frame.topLeft 时的偏移）。`drag_offset -= QPoint(delta, delta)` 等价于"drag 起点的窗口顶点跟着挪"
- **peek_wave 走 `pick_phrase` 直接 `_show_bubble` 而不是 `say_event`**：`_on_idle_phrase` 有 `edge_hidden is not None: return` 守卫，避免 IdleChatter 在小喜躲在墙边时硬塞气泡。但 peek_wave 就是要在墙边弹，所以拆出 `pick_phrase` 不发信号的纯取词 API，让 pet_window 自己决定怎么显示
- **_logical_pos 抽辅助而不是在每个 self.x() 调用处加判断**：snap 阈值检查跨两个方法（_should_snap_to_edge / _snap_to_edge），逻辑统一抽出来更稳；其他用 self.x() 的地方（如 mouseMoveEvent 拖动定位）不需要 logical，原始 self.x() 反而是要的
